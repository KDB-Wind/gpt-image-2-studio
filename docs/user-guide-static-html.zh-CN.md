# GPT-Image-2 Studio 静态 HTML 使用指南

本文面向第一次在 GitHub 接触本项目的普通用户。静态 HTML 的目标是：不安装开发环境、不运行命令，打开网页或下载一个 HTML 文件后即可使用自己的 `API key` 生图。

## 你有两种使用方式

### 在线静态页

打开：

[https://kdb-wind.github.io/gpt-image-2-studio/](https://kdb-wind.github.io/gpt-image-2-studio/)

在线版适合快速试用。你的配置保存在当前浏览器本地存储中，本项目不会接收你的 `API key`。

### 离线 HTML

从 [GitHub Releases](https://github.com/KDB-Wind/gpt-image-2-studio/releases) 下载：

```text
gpt-image-2-studio-lite.html
```

下载后双击打开即可使用。推荐浏览器：Microsoft Edge 或 Chrome。

不要下载源码列表里的根目录 `index.html`。它只是开发入口，不能独立运行。

## 适合谁

适合：

- 你已经有自己的 `API key` 和 `Base URL`。
- 你想快速使用文生图、图生图、多图参考和批量生图。
- 你不想安装桌面软件，也不想使用命令行。
- 你希望图片保存在自己的电脑上。

不适合：

- 你的供应商不允许浏览器跨域请求，也就是 CORS 不通过。
- 你不想在浏览器本地存储中保存 `API key`。
- 你需要账号、积分、平台托管 key、服务器队列或云端图片存储。

## 第一次打开

1. 打开在线静态页，或双击 `gpt-image-2-studio-lite.html`。
2. 首次进入可能会显示欢迎引导，可以关闭。
3. 先进入“设置”菜单完成配置。
4. 保存配置后，先测试文字模型和图片模型。
5. 再去“生成”或“批量”菜单使用。

默认语言是简体中文。右上角可以切换到 English，语言选择会保存在当前浏览器。

## 设置

设置保存在当前浏览器本地，不会上传到作者服务器。

必填项：

- `API key`：你的模型服务密钥。不要发到 Issue、截图或聊天记录里。
- `Base URL`：模型服务地址，例如 `https://example.com/v1`。
- 文字模型：用于提示词优化、文字模型测试和批量任务拆分。
- 图片模型：用于文生图和图生图。

如果你还没有模型服务，可以参考作者推荐中转站：

[https://ruoli.dev/register?aff=mR35](https://ruoli.dev/register?aff=mR35)

请自行评估服务稳定性、价格和合规性。

设置页提供最低限度测试：

- 测试文字模型：验证文字模型能否返回内容。
- 测试图片模型：验证文生图链路。
- 测试图生图：用内置测试图片验证图片编辑链路。

测试失败也可以保存配置，但通常说明 `API key`、`Base URL`、模型名、供应商状态或 CORS 权限存在问题。

超时时间可设置为 `60` 到 `600` 秒。快速 1K 测试可以短一些；图片模型较慢、生成 2K/4K 或提示词复杂时，建议设置为 `180` 到 `300` 秒。

## 生成

“生成”用于单次图片任务。

文生图：

1. 输入提示词。
2. 可选填写图片名称；不填时应用会按时间和提示词自动命名。
3. 可选点击“优化提示词”。
4. 点击“生成图片”。
5. 等待结果展示并保存到本地。

图生图：

1. 上传一张或多张参考图片。
2. 输入修改说明。
3. 点击“生成图片”。

当前最多支持 8 张参考图，建议不超过 4 张。图片越多，请求越大，等待时间和失败率可能更高。

常见失败：

- `401` 或 `403`：密钥错误、权限不足或模型不可用。
- `429`：供应商限流，稍后再试。
- `500`、`524`、`upstream error`：供应商或上游异常，再次调用可能仍然产生费用。
- `response did not contain any image data`：接口没有返回图片数据，通常是供应商兼容或上游异常。
- CORS 错误：供应商不允许浏览器直接访问，请改用桌面版或代理服务。

## 批量

“批量”用于一次准备多张图片。每个子任务都是独立图片请求，避免子任务之间上下文串扰。

当前保留两种方式：

- 同一提示词生成多张：适合生成多个变体。
- 自定义多条提示词：适合一次输入多张完全不同的图片需求。

自定义多条提示词：

1. 设置任务数量，默认 5，最多 20。
2. 页面会生成对应数量的提示词输入框。
3. 每个输入框代表一张图片。
4. 你可以用加号或减号增加、减少任务。
5. 点击“生成任务列表”后检查每条子任务。
6. 点击“开始批量生成”。

建议保守参数：

```text
并发数：1 到 3
间隔秒数：10 到 60
失败重试：1
```

自动重试只用于供应商明确拒绝请求的 HTTP 429。超时、HTTP 408、网络错误、5xx 和结果不明的失败不会自动重试，因为再次提交可能产生重复费用；用户仍可手动重试失败项。

如果供应商稳定，可以逐步提高并发。并发数代表同时向模型供应商发起多少个 API 请求，不是单纯占用本地内存。并发越高，供应商压力、限流概率和费用风险越高。

批量草稿会保存在本地。切换到“历史”或“设置”后再回来，主任务、任务数量和子任务提示词仍会保留。只有点击“一键清空”才会清除当前批量草稿。

批量成功生成的图片会写入历史记录，并保存批次信息。

## 历史

“历史”记录成功生成的任务，数据保存在当前浏览器本地。同一个已打开的应用实例会串行执行文件名分配、文件写入和历史更新，但浏览器文件存储与浏览器历史存储并不是一个跨存储原子事务。

如果图片文件或下载已经成功，但浏览器拒绝写入历史存储，界面会显示“仅当前会话保留历史”的成功警告。该记录在当前打开的应用实例中仍可使用，但刷新或重新打开后不会恢复。

你可以：

- 查看生成时间、模型、尺寸、耗时和输出路径。
- 查看并复用历史提示词。
- 搜索、过滤或批量删除历史记录。

HTML 版刷新后能否预览旧图片，取决于你是否在“设置”里完成目录授权。只看到目录名不代表浏览器已经能读写这个目录；请点击“选择并授权目录”，再点击“测试保存目录”。测试通过后，历史预览会优先从该授权目录恢复图片。

如果浏览器拒绝选择 `Downloads` 根目录，建议新建并授权 `Downloads/gpt-image-2-studio` 子目录，或改用 `D:\gpt-image-outputs` 这类普通目录。图片文件本身仍保存在浏览器下载目录或你授权的输出目录中。

## 隐私与安全

- `API key` 保存在当前浏览器本地存储中。
- 图片请求由你的浏览器直接发给模型供应商。
- 作者服务器不会接收你的 `API key`、提示词或图片。
- 在线静态页和离线 `file://` HTML 的浏览器存储不互通。
- 不要在公共电脑上保存 `API key`。
- 不要分享包含 `API key` 的截图或配置文件。

## CORS 自测

如果你是开发者或维护者，可以用命令测试供应商是否允许静态页访问：

```powershell
$env:BASE_URL = "https://ruoli.dev/v1"
$env:SITE_ORIGIN = "https://kdb-wind.github.io"
npm run cors:check
```

如果测试失败，说明这个供应商大概率不能被纯静态网页直接调用。
