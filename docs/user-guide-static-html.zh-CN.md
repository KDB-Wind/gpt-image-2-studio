# GPT Image 2 Studio Lite 静态 HTML 版使用指南

本文面向第一次在 GitHub 上搜索到本项目的普通用户。静态 HTML 版的目标是：不用安装开发环境，不用运行命令，下载后直接打开一个网页文件就能使用。

## 你最少需要下载什么

推荐从 GitHub Release 下载静态 HTML 版本：

- 最少文件：`index.html`
- 推荐浏览器：Microsoft Edge 或 Chrome
- 不需要下载源码
- 不需要安装 Node.js
- 不需要运行 `npm run dev`
- 不需要作者服务器

如果 Release 提供的是压缩包，请先解压，再双击打开里面的 `index.html`。

## HTML 版适合谁

适合：

- 你已经有自己的 `API key` 和 `Base URL`。
- 你想快速使用文生图、图生图和批量生图。
- 你不想安装桌面软件，也不想学习命令行。
- 你希望图片保存在自己的电脑上，而不是上传到作者服务器。

不适合：

- 你的模型供应商不允许浏览器跨域请求。
- 你不想在浏览器里保存 `API key`。
- 你需要账号、积分、平台托管 Key、服务器队列或云端图片存储。

## 第一次打开

1. 双击 `index.html`。
2. 浏览器会打开本地页面。
3. 第一次进入会看到欢迎引导，可以关闭。
4. 先进入“设置”菜单完成基础配置。
5. 保存配置后，再去“生成”或“批量”菜单使用。

页面默认语言是简体中文。右上角可以切换到 English，语言选择会保存在本机浏览器。

## 菜单一：设置

“设置”是第一次使用必须完成的步骤。配置保存在当前浏览器本地，不会上传到作者服务器。

### 连接配置

需要填写：

- `API key`：你的模型服务密钥。请不要使用别人共享的密钥，也不要把密钥发到 GitHub issue 或截图里。
- `Base URL`：模型服务地址，例如 `https://example.com/v1`。如果只填写到域名，应用会自动补齐 `/v1`。
- 文字模型：用于优化提示词、测试文字模型、AI 拆分批量任务。
- 图片模型：用于文生图和图生图。

如果你还没有模型服务，可以参考作者推荐中转站：

[https://ruoli.dev/register?aff=mR35](https://ruoli.dev/register?aff=mR35)

请自行评估服务稳定性和价格。

### 最低限度测试

设置页提供测试按钮：

- 测试文字模型：验证文字模型是否能返回内容。
- 测试图片模型：生成一张很小的测试图，验证文生图链路。
- 测试图生图：用内置测试图片验证图片编辑链路。

测试失败也可以保存配置，但失败通常说明 `API key`、`Base URL`、模型名、供应商状态或浏览器跨域权限存在问题。

### 生成默认值

常用配置：

- 超时时间：建议至少 180 秒。图片模型较慢时建议 240 到 300 秒。
- 默认尺寸：支持 `auto`、1K、2K、4K 和自定义宽高。
- 图片数量：单次生成 1 到 4 张。
- 质量：`auto`、`low`、`medium`、`high`。
- 格式：`png`、`jpeg`、`webp`。
- 压缩质量：仅对 `jpeg` 和 `webp` 生效。

高分辨率图片可能更慢，也可能不被某些兼容供应商支持。如果不确定，先用 `1024x1024` 或 `auto` 测试。

### 输出目录

HTML 版有两种保存方式：

- 如果浏览器支持目录选择，会让你选择一个本地目录。
- 如果浏览器不支持目录选择，会使用浏览器下载功能保存图片。

Microsoft Edge 和 Chrome 对本地目录选择支持较好。Firefox 和部分浏览器可能只能下载文件。

### 保存配置

填写完成后点击“保存配置”。配置会写入当前浏览器的本地存储。清理浏览器数据、换浏览器或换电脑后，需要重新填写。

## 菜单二：生成

“生成”用于单次图片任务。

### 文生图

1. 在提示词输入框描述你想要的画面。
2. 可选填写图片名称。不填写时，应用会按时间和提示词自动命名。
3. 可选点击“优化提示词”，让文字模型先改写提示词。
4. 点击“生成图片”。
5. 等待图片生成完成。
6. 图片会显示在结果预览区，并保存到本地。

建议提示词包含主体、风格、构图、颜色、场景和用途。例如：

```text
为法国国家队生成一张 2026 年世界杯宣传海报，使用法语文字，蓝白红配色，电影海报风格，主体清晰，适合社交媒体封面。
```

### 图生图

1. 上传一张或多张参考图片。
2. 输入你希望如何修改图片。
3. 点击“生成图片”。

有参考图片时，应用会调用图片编辑接口；没有参考图片时，应用会调用文生图接口。

当前支持最多 8 张参考图片，建议不超过 4 张。图片越多，请求越大，失败率和等待时间也可能更高。

### 拖拽上传

你可以把图片文件从文件夹直接拖到上传区域。上传后可以移除单张图片，也可以继续补充图片。

### 常见生成失败

- `Request timed out`：图片模型生成时间超过超时时间，去设置页增大超时。
- `status 401` 或 `status 403`：`API key` 错误、权限不足或模型不可用。
- `status 429`：供应商限流，稍后再试。
- `status 500`、`524`、`upstream error`：请求到达供应商或中转站，但上游异常。再次调用可能仍然产生费用，建议等待供应商恢复。
- `response did not contain any image data`：接口返回成功但没有图片数据，通常是供应商兼容或上游异常。
- CORS 报错：供应商不允许浏览器直接访问，请改用桌面版或代理服务。

## 菜单三：批量

“批量”用于一次准备多张图。每个子任务都是独立图片请求，避免不同任务之间的上下文串扰。

### 三种批量来源

同一提示词生成多张：

适合用同一句提示词生成多个变体。设置任务数量后点击“生成任务列表”。

多行提示词排队：

适合你已经准备好多条提示词。每一行会变成一个独立子任务。

AI 拆分：

适合你只有一个主任务，希望文字模型帮你拆成 N 条风格一致、主体不同的子提示词。例如输入“为法国 / 日本 / 比利时 / 韩国生成世界杯宣传海报，使用该国家的母语”，任务数量设为 4，然后点击“调用文字模型拆分”。

### AI 拆分模板

当前内置几个轻量拆分模板：

- 基础拆分
- 风格一致拆分
- 系列作品拆分
- 自定义 `systemPrompt`

这些模板只负责把主任务拆成子任务，不负责直接生图。拆分完成后，你可以逐条修改标题和提示词，再开始批量生成。

提示词模板能力目前不是核心功能，后续计划移除后重新设计为独立菜单。

### 批量参数

- 批次名称：用于输出目录和 `manifest.json`。
- 任务数量：AI 拆分或同一提示词模式下使用。
- 并发数：同时发起多少个图片请求。默认 1，最大 3。供应商不稳定时建议保持 1。
- 间隔秒数：每次请求之间等待多久。默认 20 秒，范围 0 到 300 秒。
- 失败重试：单个任务失败后自动重试次数。默认 1，最大 3。

如果模型供应商负载能力不明确，建议先使用：

```text
并发数：1
间隔秒数：20 到 60
失败重试：1
```

### 批量执行

1. 选择批量来源。
2. 输入主任务或多行提示词。
3. 点击“生成任务列表”或“调用文字模型拆分”。
4. 检查并微调每个子任务。
5. 点击“开始批量生成”。
6. 等待全部任务完成、失败或跳过。

执行中可以暂停或取消。失败的子任务会显示错误信息，任务结束后可以点击“重试该任务”。

### 批量保存

成功生成的图片会写入历史记录。批量任务还会生成 `manifest.json`，记录批次 ID、批次标题、任务参数、每个子任务的提示词、状态、耗时和输出路径。

如果浏览器允许目录写入，图片会保存到一个批次目录中；否则浏览器会逐个下载图片和 `manifest.json`。

### 成本风险暂停

如果供应商返回“可能已经产生调用成本但没有图片”的异常，批量任务会暂停，避免继续消耗调用成本。你可以等待供应商恢复后再手动继续或重试。

## 菜单四：历史

“历史”记录成功生成的图片任务，数据保存在当前浏览器本地。

你可以：

- 查看生成时间、模型、尺寸、耗时和输出路径。
- 选择历史记录查看提示词。
- 复用历史提示词重新生成。

HTML 版不能保证刷新后仍能直接预览旧图片，因为浏览器不允许网页随意读取本地文件。图片文件本身已经保存在下载目录或你选择的输出目录中，请到本地文件夹查看。

清理浏览器数据会删除历史记录，但不会删除已经下载到电脑上的图片文件。

## 隐私与安全

- `API key` 保存在当前浏览器本地存储中。
- 图片请求由你的浏览器直接发给模型供应商。
- 作者服务器不会接收你的 `API key`、提示词或图片。
- 不要在公共电脑上保存 `API key`。
- 不要把包含 `API key` 的截图、配置文件或浏览器数据发给别人。

## HTML 版和基础工具源码/桌面版区别

| 项目 | 静态 HTML 版 | 源码网页版 | 桌面版 |
| --- | --- | --- | --- |
| 启动方式 | 双击 `index.html` | `npm run dev` | 安装包或 `npm run desktop:dev` |
| 是否需要 Node.js | 不需要 | 需要 | 开发时需要 |
| 是否需要后端 | 不需要 | 不需要 | 不需要 |
| 保存方式 | 浏览器下载或目录选择 | 浏览器下载或目录选择 | 本地应用原生保存 |
| CORS 影响 | 会受影响 | 会受影响 | 通常更少受影响 |
| 适合用户 | 普通用户快速试用 | 开发者本地调试 | 普通用户长期使用 |

## 故障排查

如果完全无法请求模型：

1. 检查 `Base URL` 是否以 `/v1` 结尾。
2. 检查 `API key` 是否有效。
3. 检查文字模型和图片模型名称是否和供应商后台一致。
4. 先测试文字模型，再测试图片模型。
5. 打开浏览器开发者工具，看是否有 CORS 报错。
6. 如果是供应商 `500`、`524` 或 `upstream error`，等待供应商恢复。

如果图片生成很慢：

1. 把超时时间调到 240 或 300 秒。
2. 降低图片尺寸。
3. 批量任务把并发数设为 1。
4. 批量任务把间隔秒数设为 20 到 60。

如果找不到保存的图片：

1. 检查浏览器下载目录。
2. 如果选择过输出目录，到该目录按日期或批次名称查找。
3. 批量任务查找同名批次目录和 `manifest.json`。
