# 基础工具版使用指南

基础工具版是本项目的本地工具形态，适合自己配置 `API key` 后在本机使用。它和单文件 HTML 版功能接近，但启动方式和本地保存能力不同。

如果你只是想最快开始使用，请优先阅读 [单文件 HTML 使用指南](./user-guide-static-html.zh-CN.md)。

## 版本选择

| 方式 | 适合人群 | 启动方式 |
| --- | --- | --- |
| 单文件 HTML | 普通 GitHub 用户快速试用 | 下载 `gpt-image-2-studio-lite.html` 后双击打开 |
| 源码网页模式 | 开发者或愿意运行命令的用户 | `npm run dev` |
| 桌面版 | 普通用户长期使用 | Windows 安装包或 `npm run desktop:dev` |

基础工具版不包含平台注册、积分、平台托管 Key、支付、管理员后台、服务端队列或服务端图片存储。

## 源码网页模式

要求：

- Node.js `>= 20.19.0`
- npm `>= 10`

启动：

```powershell
npm install
npm run dev
```

启动后访问终端显示的地址，通常是：

```text
http://localhost:5173/
```

## 桌面版

桌面版更适合长期本地使用。

开发模式：

```powershell
npm run desktop:dev
```

打包：

```powershell
npm run desktop:build
```

## 设置

第一次使用必须先进入“设置”。

必填项：

- `API key`：你的模型服务密钥。
- `Base URL`：模型服务地址，建议使用 `/v1` 结尾。
- 文字模型：用于提示词优化、AI 拆分批量任务和文字测试。
- 图片模型：用于文生图、图生图和图片测试。
- 超时时间：建议至少 `180` 秒，图片模型较慢时建议 `240` 到 `300` 秒。

图片默认参数：

- 尺寸：`auto`、1K、2K、4K 或自定义宽高。
- 数量：1 到 4。
- 质量：`auto`、`low`、`medium`、`high`。
- 格式：`png`、`jpeg`、`webp`。
- 压缩质量：仅对 `jpeg` 和 `webp` 生效。

建议按顺序测试：

1. 测试文字模型。
2. 测试图片模型。
3. 如果要用图生图，再测试图片编辑模型。

测试失败仍可保存配置，但需要根据错误信息检查供应商、密钥、模型名和网络状态。

## 生成

“生成”用于单次图片任务。

文生图：

1. 输入提示词。
2. 可选填写图片名称。
3. 可选优化提示词。
4. 点击生成。
5. 等待图片保存和预览。

图生图和多图参考：

上传或拖拽图片后，再输入修改说明。当前最多支持 8 张参考图，建议不超过 4 张。

没有参考图时，应用调用 `/images/generations`。有参考图时，应用调用 `/images/edits`。

## 批量

批量菜单支持三种方式：

- 同一提示词生成多张：适合做风格变体。
- 多行提示词排队：每一行是一张图。
- AI 拆分：用文字模型把一个主任务拆成 N 条子提示词。

建议保守参数：

```text
并发数：1
间隔秒数：20 到 60
失败重试：1
```

如果供应商稳定，可以逐步提高并发，但当前最大并发限制为 3。供应商异常时，批量任务可能自动暂停，避免继续产生无效成本。

批量生成成功后会写入历史记录，并保存 `manifest.json`。

## 历史

历史记录成功生成的任务。你可以查看提示词、模型、尺寸、耗时和输出路径，也可以复用提示词。

源码网页模式和单文件 HTML 的历史主要保存在浏览器本地。桌面版更适合长期保存和打开本地目录。

## 关于提示词模板

当前基础工具版里可能存在提示词模板相关入口，但它不是核心流程。后续计划移除当前实现，并重新开发一个更清晰的独立菜单。

现阶段建议主要使用：

- 生成页的提示词输入。
- 批量页的 AI 拆分。
- 自定义拆分 `systemPrompt`。

npm run build:static
```

cargo check --manifest-path src-tauri/Cargo.toml
```
