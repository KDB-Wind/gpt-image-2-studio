# 基础工具版使用指南

基础工具版是本项目的本地工具形态，适合自己配置 `API key` 后在本机使用。它和静态 HTML 版的功能基本一致，但启动方式和本地保存能力不同。

如果你是普通用户，并且只想最快使用，请优先阅读 [静态 HTML 版使用指南](user-guide-static-html.zh-CN.md)。

## 版本选择

基础工具版目前有三种使用方式：

| 方式 | 适合人群 | 启动方式 |
| --- | --- | --- |
| 静态 HTML 版 | 普通 GitHub 用户快速试用 | 双击 `index.html` |
| 源码网页模式 | 开发者或愿意运行命令的用户 | `npm run dev` |
| 桌面版 | 普通用户长期使用 | 安装包或 `npm run desktop:dev` |

基础工具版不包含平台注册、积分、平台托管 Key、支付、管理员后台、服务端队列和平台图片存储。

## 源码网页模式快速启动

前置要求：

- Node.js `>= 20.19.0`
- npm `>= 10`

启动步骤：

```powershell
npm install
npm run dev
```

启动后浏览器访问终端显示的地址，通常是：

```text
http://localhost:5173/
```

如果 5173 端口被占用，可以关闭占用端口的旧进程，或按 Vite 提示使用新的端口。

## 桌面版

桌面版适合不想每次打开命令行的用户。它可以通过安装包使用，也可以在开发环境中运行：

```powershell
npm run desktop:dev
```

打包：

```powershell
npm run desktop:build
```

桌面版通常比浏览器版更适合长期使用，因为本地保存和打开目录的体验更接近普通软件。

## 菜单一：设置

第一次使用必须先进入“设置”。

### 必填项

- `API key`：你的模型服务密钥。
- `Base URL`：模型服务地址，建议使用 `/v1` 结尾。
- 文字模型：用于提示词优化、AI 拆分批量任务和文字测试。
- 图片模型：用于文生图、图生图和图片测试。
- 超时时间：建议至少 180 秒，图片模型慢时建议 240 到 300 秒。

### 图片默认参数

- 尺寸：`auto`、1K、2K、4K 或自定义宽高。
- 数量：1 到 4。
- 质量：`auto`、`low`、`medium`、`high`。
- 格式：`png`、`jpeg`、`webp`。
- 压缩质量：仅对 `jpeg` 和 `webp` 生效。

### 输出目录

源码网页模式下，图片通常通过浏览器下载或浏览器目录选择保存。

桌面版会更接近原生本地软件，可以更稳定地保存到你设置的目录。

### 测试连接

建议按顺序测试：

1. 测试文字模型。
2. 测试图片模型。
3. 如果你要用图生图，再测试图片编辑模型。

测试失败仍可保存配置，但需要根据错误信息检查供应商、密钥、模型名和网络状态。

## 菜单二：生成

“生成”用于单次图片任务。

### 文生图

1. 输入提示词。
2. 可选填写图片名称。
3. 可选优化提示词。
4. 点击生成。
5. 等待图片保存和预览。

### 图生图和多图参考

上传或拖拽图片后，再输入修改说明。当前最多支持 8 张参考图，建议不超过 4 张。

如果没有参考图片，应用调用 `/images/generations`。如果有参考图片，应用调用 `/images/edits`。

## 菜单三：批量

批量菜单支持三种方式：

- 同一提示词生成多张：适合做风格变体。
- 多行提示词排队：每一行是一张图。
- AI 拆分：用文字模型把一个主任务拆成 N 条子提示词。

批量建议参数：

```text
并发数：1
间隔秒数：20 到 60
失败重试：1
```

如果供应商稳定，可以逐步提高并发，但当前最大并发限制为 3。供应商异常时，批量任务可能自动暂停，避免继续产生无效成本。

批量生成成功后会写入历史记录，并保存 `manifest.json`。

## 菜单四：历史

历史记录成功生成的任务。你可以查看提示词、模型、尺寸、耗时和输出路径，也可以复用提示词。

源码网页模式和静态 HTML 版的历史主要保存在浏览器本地。桌面版更适合长期保存和打开本地目录。

## 关于提示词模板

当前基础工具版里可能存在提示词模板相关入口，但它不是核心流程。后续计划移除当前实现，并重新开发一个更清晰的独立菜单。

现阶段建议主要使用：

- 生成页的提示词输入
- 批量页的 AI 拆分
- 自定义拆分 `systemPrompt`

## 常见问题

### 页面打开但无法生图

检查 `API key`、`Base URL`、模型名称和供应商状态。浏览器模式还需要检查 CORS。

### 生成很慢

图片模型通常需要较长时间。把超时时间设为 240 到 300 秒，并降低图片尺寸测试。

### 供应商报 500、524 或 upstream error

这通常不是本地程序逻辑错误，而是供应商或上游异常。再次调用可能产生费用，建议等待恢复后再试。

### 批量任务切换菜单后还在吗

当前批量草稿会在本地保留，切换菜单后应继续存在。点击“一键清空”后才会清掉当前批量输入和子任务。

## 开发者验证命令

```powershell
npm run test:run
npm run build
npm run build:static
```

如果要验证桌面端，还需要 Rust 和 Tauri 环境：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
```
