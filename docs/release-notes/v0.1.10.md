# v0.1.10 — Reliability and maintenance

## 中文

- 修复接口收到响应头后超时提前失效的问题；超时现在覆盖完整 JSON 响应体，异常成功响应会脱敏并停止有计费风险的批量调用。
- 统一 Web 与桌面图片 URL 下载：增加完整下载超时，遵守强制 base64，拒绝空内容及 HTML/JSON 网关错误，下载失败不会自动再生图。
- 修复旧历史预览失败覆盖新选中结果的问题，补上批次预览失败提示，同时保留仍可用的旧预览。
- 设置中明确清空并保存 API key 会删除当前 Web 档案的旧凭据；损坏的密钥映射可安全恢复，退出记住的遗留密钥移至会话存储。
- 删除当前供应商档案前水合剩余档案，避免空占位符清除桌面持久凭据；换供应商重试的结果记录实际供应商。
- 批量最后一张完成后不再空等；间隔和限流冷却期间可及时暂停/取消；Retry-After、指数退避及累计等待预算限制重试；配额和账单问题停止自动调用。
- 恢复批量草稿时保留脱敏的供应商归属、保存持久性和恢复建议。
- 取消目录选择不再报错或丢失旧目录；不支持目录授权的浏览器可以通过下载开始使用；缺少 randomUUID 仍可上传参考图并保存图片。
- 更新受影响的 npm 依赖和 Tauri；PR CI 增加 Windows/Linux/macOS Chromium 及手机布局回归，测试 helper 保留显式传入的供应商档案。
- 保留全部历史静态版本，准备新的可复现静态归档。此文件和本地候选不代表 GitHub Release 或 Pages 已发布。

## English

- Keep request deadlines active through JSON response-body consumption; redact malformed accepted responses and stop batches with uncertain generation costs.
- Share bounded image downloads across Web and desktop, honor force-base64, and reject empty or HTML/JSON gateway payloads.
- Ignore stale history failures and report batch-preview errors while preserving usable previews.
- Distinguish explicit API-key clearing from unhydrated metadata, retain independent profile credentials, and recover malformed key maps.
- Hydrate remaining credentials before profile deletion and record the provider used for each retried request.
- Finish batches without a trailing interval; respond to pause/cancel during waits; honor Retry-After with bounded exponential backoff and stop on quota/billing errors.
- Preserve sanitized provenance, storage durability, and recovery actions when restoring batch drafts.
- Treat folder-picker cancellation as a no-op, allow download-only onboarding, and support reference upload and history saves without randomUUID.
- Update affected dependencies and add pre-merge browser coverage on Windows, Linux, and macOS, including mobile layouts.
- Preserve historical archives and prepare a reproducible candidate. Publication status must be verified separately.
