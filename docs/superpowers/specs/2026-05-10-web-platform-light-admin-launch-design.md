# Web 平台一期轻后台上线设计

Date: 2026-05-10

## 目标

把当前项目收敛为可公开上线的 Web 平台一期版本，只保留最小可运营闭环：

- 邮箱注册 / 登录
- 兑换码换积分
- 平台托管 key 生图
- 图生图与文本生图
- 轻量管理员后台
- 多供应商 key 池
- 分层熔断与成本监控

一期不做站内支付，只做兑换码；不做充值申请，不做用户自带 key 主路径，不做社区广场，不做开放 API。

## 产品边界

### 对外定位

对外可定位为“AI 设计创作工具”或“设计辅助服务”，但系统实现上仍按公开 Web 服务处理，不能把改名当作合规替代。

### 一期必须保留

- 邮箱验证码注册 / 登录
- 兑换码兑换积分
- 平台托管 key 生图
- 文生图、图生图、多图上传、拖拽上传
- 任务历史
- 管理员首页
- 兑换码管理
- 用户管理
- 积分流水
- 任务尝试明细
- 供应商线路与熔断页

### 一期不做

- 站内支付
- 充值申请
- 用户自带 key 主路径
- 公开作品广场
- 评论 / 收藏 / 社交
- 自动退款
- 复杂角色体系
- 完整 BI 报表

## 核心数据模型

### 1. supplier

`supplierId -> baseUrl` 为 `1:1`。

它表示一个供应商组，主要用于路由统计和风险归因。

### 2. providerModel

`supplierId + baseUrl + imageModel` 表示一个实际调度单元。

它是主要熔断层，也是健康探测层。

### 3. apiKey

`providerModel -> apiKey` 为 `1:n`。

一个模型下可以挂多个 key，自动路由、自动重试和 key 级熔断都作用在这一层。

### 4. generationJob

用户视角的一次生图请求。

### 5. generationAttempt

平台实际向上游发起的一次调用尝试。

这张表是成本监控的关键。用户看到的是 job 成功或失败，管理员看到的是每一次 attempt 的真实结果。

### 6. creditLedger

只记录用户积分变动，不记录上游尝试。

### 7. providerStateEvent

记录 key / providerModel 的熔断、恢复、降级。

### 8. adminAuditLog

记录管理员动作。

## 存储策略

### 用户侧必须配置存储 / 下载地址

电脑网页端和手机网页端都必须先配置一个图片存储 / 下载地址，并通过系统提供的测试图片验证成功后，才能进入生图流程。

这个地址是用户级配置，优先作为生成结果的长期存储位置。为了兼容多终端，配置应同时支持：

- 账号级保存，登录后跨设备可复用
- 终端本地缓存，便于再次打开时自动预填

### 生图前的强校验

在允许用户点击“生成”之前，前台必须完成一次存储连通性测试：

1. 系统提供一张测试图片地址
2. 客户端尝试按当前配置完成一次下载 / 写入验证
3. 验证成功后，生成按钮才可用
4. 验证失败时，不允许发起生图

### 平台侧图片保留策略

服务器只有有限的 OSS 存储预算，因此平台侧只保留最近 7 天的图片副本和访问索引。

要求：

- 最近 7 天内的结果图片可在平台侧直接查看和下载
- 超过 7 天后，服务器侧图片副本自动清理
- 历史任务记录仍保留元数据
- 用户长期访问应依赖其配置的存储 / 下载地址

### 存储失败处理

- 若用户未配置地址或测试失败，禁止进入生图
- 若运行时写入存储失败，任务记为失败
- 存储失败不扣用户积分
- 管理员后台必须能看到该失败对应的 attempt 记录

## 路由策略

### 后台自动切换重试

用户发起一次 job 后：

1. 先选一个可用 `providerModel`
2. 再选一个可用 `apiKey`
3. 如果该 key 出现成本风险失败，自动切到同一 `providerModel` 下的下一个可用 key
4. 默认最多自动重试 1 次
5. 若仍失败，则 job 失败返回给用户

前台不展示重试细节，用户只看到最终成功或失败结果；重试过程只记录在 `generationAttempt` 和后台审计中。

### 选择权重

候选 key 可按以下因素打分：

- 最近成功率
- 最近失败率
- 当前并发
- 最近使用时间
- 最近成本风险失败数
- 管理员手动权重

## 分层熔断

### key 级

单个 key 出现异常时，先封这个 key，不立即封整个 providerModel。

适用情况：

- 429
- 鉴权失败
- 速率限制
- 单 key 明显异常

### providerModel 级

同一 `supplierId + baseUrl + imageModel` 下，多个不同 key 在短时间内出现同类成本风险失败时，升级为 providerModel 熔断。

适用情况：

- 524
- `openai_error`
- 空数组 / 解析失败
- 返回空图
- 响应成功但无图片数据
- 其他已确认可能计费但未出图的错误

### supplier 级

一期先只做统计视图，不做强制全量封禁。

## 成本与扣费规则

### 用户扣费

- 只有 `generationJob` 最终成功出图时才扣积分
- 自动重试过程中的失败不扣用户积分
- job 最终失败则不扣用户积分

### 平台成本监控

管理员必须按 `generationAttempt` 统计成本，而不是按 job 统计。

建议 attempt 状态：

- `rejected`
  - 429、鉴权失败、未真正进入上游处理
  - 记为无成本失败
- `failed_no_cost`
  - 明确无成本失败
- `failed_likely_billed`
  - 请求已经打到上游，但没返回可用图片，可能产生费用
- `success`
  - 成功返回图片

### 管理员必须看到的指标

- 今日成功出图数
- 今日 job 失败数
- 今日上游实际调用数
- 今日疑似已计费失败数
- 当前熔断中的 providerModel 数
- 当前可用 key 数

- 搜索用户
- 查看积分

- 查看兑换入账

### 线路与熔断页

## 注册与风控

- 仅邮箱注册
- 验证码短有效期
- 限制同邮箱发送频率
- 限制同 IP 注册频率
- 限制同设备短时间兑换失败次数
- 不做手机号，不做复杂实名

## 验收标准

### 功能

- 用户可注册并登录
- 用户可兑换兑换码并获得积分
- 用户可使用平台托管 key 生图
- 文本生图和图生图都可用
- 后台自动切 key 重试可用
- 用户失败不扣积分
- 管理员可看到 attempt 级成本统计
- 用户可先完成存储 / 下载地址配置并通过测试
- 平台侧仅保留最近 7 天图片副本

### 稳定性

- 单 key 异常不会立刻打穿整条 providerModel
- 需要时能对 providerModel 熔断
- 健康探测只默认探测 1 个 key

### 运营

- 管理员可发兑换码
- 管理员可查看成本风险
- 管理员可禁用异常 key
- 管理员可恢复线路

## 非目标

- 完整自动支付
- 用户自助充值
- 高级权限系统
- 公开社区
- 自动扩展到多供应商全量切换
- 完整自动退款
