# 产品版本边界

本项目后续会同时保留两个版本方向：基础工具版和 Web 平台版。两者共享图片配置、Provider Adapter、提示词模板等中立能力，但用户体系、额度、支付、队列和平台存储只属于 Web 平台版。

## 基础工具版

基础工具版面向个人本地使用，也适合作为后续 GitHub 开源版本。它的目标是轻量、开箱即用、易于普通用户理解，不要求用户部署服务器。

保留能力：

- 本地填写并保存 `API key`、`Base URL`、文字模型、图片模型。
- 文生图、图生图、多图参考和拖拽上传。
- 图片尺寸、质量、分辨率、超时和输出目录配置。
- 生成图片保存到用户本地目录。
- 提示词模板库，帮助小白快速选择人物、毕业照、肖像、商品图、海报等场景。
- Windows 桌面安装包。
- 可选的纯本地轻量页面体验。

不包含能力：

- 用户注册、登录和 session。
- 平台托管 API key。
- 积分、支付、充值和管理员审核。
- Redis 队列、Worker、PostgreSQL。
- 平台图片存储和平台历史记录。
- 服务端健康探测和供应商熔断。
- 任何会把用户自己的 API key 上传到平台服务器的功能。

## Web 平台版

Web 平台版面向普通网页用户，由站点维护者部署和运营。它允许用户不理解 API key，也可以通过平台注册、体验和付费使用托管生图能力。

保留两种使用模式：

- 自有 API key 模式：用户自己填写 `Base URL`、`API key`、模型名等配置，配置只保存在浏览器本地，不占用平台存储。
- 平台托管 Key 模式：用户注册登录后使用平台额度，由后端统一调度托管 API key、队列、扣费、健康探测和供应商熔断。

平台专属能力：

- 邮箱验证码注册和登录。
- Web 平台工作台：服务状态、额度、提示词模板、托管任务提交和任务历史。
- 生产 SMTP 验证码发送和进程内验证码请求限流。
- 固定二维码人工充值申请，管理员审核通过后发放额度。
- 管理员工作台：支付审核、健康探测频率配置。
- 每日免费体验额度。
- 积分流水、成功后扣额度、失败不扣用户额度。
- 管理员加额度、禁用用户、审核支付。
- BullMQ 队列和 Worker。
- PostgreSQL 持久化用户、任务、额度、模板、供应商状态和审计日志。
- Redis 队列。
- 平台托管图片存储。
- 供应商健康探测和成本风险熔断。
- 管理接口和后续管理后台 UI。

## 共享包边界

应继续保持共享包不依赖平台业务：

- `packages/image-config`：只处理图片生成配置和上传限制。
- `packages/provider`：只处理 OpenAI-compatible 图片接口调用和响应解析。
- `packages/prompt-templates`：只处理提示词模板、分类和变量渲染。
- `packages/platform-core`：可以包含供应商熔断、API key 路由、费用策略等纯逻辑，但不直接依赖 Fastify、PostgreSQL、Redis 或 Tauri。

这样基础工具版可以复用核心生图能力，而不会被用户、支付、队列、数据库等平台逻辑拖重。

## 下一阶段优先级

1. 模板管理后台：模板启停、编辑、导入来源和分类维护。
2. 自动支付：从人工二维码审核升级到微信支付回调或第三方支付网关。
3. CI/CD 与部署演练：把 migration、备份、回滚、日志轮转脚本接入真实服务器流程。
4. 基础工具版开源整理：拆出无平台依赖的入口、README、示例配置和许可证。
5. 风控增强：注册设备指纹、IP 限流持久化、异常任务告警和人工风控记录。
